# Security policy

## Reporting a vulnerability

Please do not disclose vulnerability details, exploit code, credentials, private keys, wallet recovery phrases, or sensitive personal data in public issues, discussions, or pull requests.

Use GitHub’s **Report a vulnerability** function in the repository’s **Security** tab to submit a private vulnerability report when that option is available. If private reporting is unavailable, use the contact route on the [official website](https://orakzaibond.com) and request a private security contact channel; do not include exploit details in a public message.

Please include the affected repository and version or commit, impact and prerequisites, a concise reproduction or proof of concept that does not access third-party data, and any suggested mitigation. Allow time for investigation and coordinated remediation before public disclosure. Do not test against live systems or assets without explicit authorization.

## Scope and status

This policy applies to code and documentation maintained in the Orakzai-Bond GitHub organization. A report is not confirmation that a product, service, smart contract, or deployment is live. Security review, audit, or remediation status will be stated only when supported by verifiable evidence. Do not infer an audit, certification, or regulatory approval from this policy.

## Response

The project will make reasonable efforts to acknowledge a report, validate its scope, coordinate a fix where feasible, and communicate material status updates through the private channel. No response-time guarantee is made.
