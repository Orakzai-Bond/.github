# Contributing

Thank you for helping improve Orakzai Bond’s public code and documentation. Repository-specific instructions take precedence over these shared defaults.

## Before you contribute

1. Read the repository README, license, and `SECURITY.md`.
2. Check existing issues and pull requests to avoid duplicate work.
3. For substantial changes, open an issue first to discuss scope. Do not post security vulnerabilities publicly; use the private process in `SECURITY.md`.
4. Do not submit secrets, wallet keys or seed phrases, real user data, or unsupported claims about deployments, audits, partnerships, investment returns, or regulatory status.

## Pull requests

- Keep changes focused and explain the problem, approach, and relevant limitations.
- Link related issues and include tests or reproducible verification where appropriate.
- Update documentation when behavior, configuration, or project status changes.
- Disclose new dependencies and explain why they are needed.
- Do not include generated files or unrelated formatting changes unless necessary.

## Quality and communication

Follow existing style and repository checks. Be respectful, factual, and constructive under the [Code of Conduct](CODE_OF_CONDUCT.md). Contributors are responsible for ensuring they have the rights to submit their contributions. A submission does not imply acceptance or a particular release timeline.
